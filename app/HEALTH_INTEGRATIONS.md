# «Цифровой управляющий» — показатели здоровья (v286)

## Реализовано в PWA

- Четвёртая вкладка **«Показатели»**, первая при открытии «Моего здоровья».
- Ручной ввод давления (систолическое/диастолическое, мм рт. ст.), пульса (уд/мин), шагов (дневной итог).
- Несколько записей давления и пульса в сутки; для ручных шагов — одна изменяемая запись на дату.
- Последние значения, история, фильтр по виду и семидневный график шагов. Отсутствующие значения **не заменяются демонстрационными**.
- Локальное IndexedDB-хранилище `digital-manager-private-health-v1` обновляется с версии **1 до 2** с добавлением хранилища `metrics`. Старые хранилища `settings`, `meds`, `logs`, `sleep`, `docs` не очищаются.
- Общий JSON-экспорт версии 2 включает `metrics` и прежние записи, но не содержит бинарные медицинские документы.
- Всё включается только после прежнего явного согласия пользователя. Нет сервера, аккаунта, облачного копирования или шифрования; данные может увидеть любой с доступом к браузерному профилю.

## Что НЕ реализовано

**Веб-приложение/PWA не умеет напрямую читать HealthKit/Apple Health и Health Connect или показывать собственные осложнения циферблата Apple Watch / Wear OS.** Статус устройств в интерфейсе честно показывает отсутствие нативной интеграции. Никаких фиктивных измерений и фиктивного состояния «подключено» нет.

Для будущей функциональности понадобятся отдельные компоненты:

- **iOS:** приложение/обёртка с HealthKit entitlement и пояснением цели доступа в Info.plist; для Apple Watch — отдельная часть watchOS/WidgetKit. Пользователь выдаёт разрешение для каждого считываемого типа.
- **Android:** приложение/обёртка с Health Connect SDK/API, объявлениями необходимых разрешений на данные, проверкой наличия Health Connect и экраном системного согласия; для Wear OS — отдельный интерфейс.
- **Передавать показатели на часы** и **читать показатели с часов** — разные функции. Текущая подготовка касается только локального импорта при открытом приложении, а не фоновой синхронизации, пушей или циферблата.

## Контракт адаптера

`health-bridge.js` публикует `window.DMHealthBridge`, без фоновых действий. Нативный слой может зарегистрировать адаптер, когда устройство готово:

```js
window.DMHealthBridge.register('apple-health', {
  async requestReadAuthorization(types) {
    // Только после нажатия пользователем на кнопку синхронизации:
    // вызвать системный экран разрешений HealthKit, вернуть true лишь
    // когда нативный слой разрешает выполнять запрос.
  },
  async readDailyMeasurements({ from, to, types }) {
    // Вернуть измерения пользователя за указанные даты:
    return [
      { id:'stable-native-id-1', type:'pressure', date:'2026-10-10', time:'09:10', systolic:120, diastolic:80 },
      { id:'stable-native-id-2', type:'pulse', date:'2026-10-10', time:'09:11', bpm:72 },
      { id:'daily-summary-id', type:'steps', date:'2026-10-10', steps:6500 }
    ];
  }
});
```

Аналогично `register('health-connect', adapter)`.

Важно: приведённые числа **только пример структуры для разработчика**. Приложение само не создаёт тестовых измерений и не показывает эти значения человеку.

### Правила импорта

- `readOnUserAction(provider, from, to)` вызывается **только по нажатию** кнопки и предварительно вызывает системную авторизацию.
- `from/to/date` в `YYYY-MM-DD`, `time` в `HH:mm` (при отсутствии — `12:00`).
- Для давления и пульса нативный адаптер должен предоставить **стабильный идентификатор образца** `id`; повторный импорт перезапишет такой образец, а не задвоит.
- `steps` должно быть **суточным агрегатом от одного провайдера**, НЕ суммой пересекающихся сырых интервалов. Ключ `import:<provider>:steps:<date>` гарантирует одно значение от провайдера за день. Не суммировать источники между собой (например, телефон + часы).
- `type`: `pressure` с `systolic`, `diastolic`; `pulse` с `bpm`; `steps` с `steps`.
- Подписи источника `manual`, `apple-health`, `health-connect` сохраняются отдельно; ручной шагомер имеет приоритет при показе одного дня, но записи других источников остаются в истории.
- Экспорт и удаление локальные. Интерфейс не оценивает медицинские нормы и не заменяет врача.

## Минимальная проверка перед публикацией нативных обёрток

1. На устройстве с уже сохранёнными лекарствами/сном открыть новую сборку и проверить автоматическую миграцию IDB 1→2 **без потери старых данных**.
2. Без согласия: новая вкладка и измерения недоступны. После согласия: добавить и отредактировать давление, пульс, шаги, включая ноль шагов.
3. Проверить смену даты для ручных шагов, подтверждение удаления, фильтр, семидневный график, экспорт JSON и «Удалить всё».
4. Без нативного адаптера кнопка импорта не показывается; статус **не утверждает**, что часы подключены.
5. В нативной оболочке протестировать отказ в разрешении, отозванные разрешения, пустые данные, повторный импорт и совместное ношение часов и телефона без двойного подсчёта шагов.
6. Перед настоящей синхронизацией, бэкапом в облако или доступом с другого устройства нужен отдельный проект защищённого хранения, политики приватности и управления доступом.
